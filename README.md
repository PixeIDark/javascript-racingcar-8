# javascript-racingcar-precourse

## 프로젝트 개요

초간단 자동차 경주 게임을 구현하는 프리코스 미션입니다. 주어진 횟수 동안 n대의 자동차가 경주하여 우승자를 결정합니다.

## 주의 사항

- **프로그램 종료 시 process.exit()를 호출하지 않는다.**
- 프로그래밍 요구 사항에서 달리 명시하지 않는 한 파일, 패키지 등의 이름을 바꾸거나 이동하지 않는다.
- 자바스크립트 코드 컨벤션을 지키면서 프로그래밍한다.
- 기본적으로 JavaScript Style Guide를 원칙으로 한다.
- **indent(인덴트, 들여쓰기) depth를 3이 넘지 않도록 구현한다. 2까지만 허용한다.**
    - 예를 들어 while문 안에 if문이 있으면 들여쓰기는 2이다.
    - 힌트: indent(인덴트, 들여쓰기) depth를 줄이는 좋은 방법은 함수(또는 메서드)를 분리하면 된다.
- **3항 연산자를 쓰지 않는다.**
- **함수(또는 메서드)가 한 가지 일만 하도록 최대한 작게 만들어라.**
- Jest를 이용하여 정리한 기능 목록이 정상적으로 작동하는지 테스트 코드로 확인한다.
- Random 값 추출은 Random.pickNumberInRange()를 활용한다.
  ```js
  MissionUtils.Random.pickNumberInRange(0, 9); // 0이상 9이하 정수 반환
  ```
- 사용자의 값을 입력 및 출력하려면 Console.readLineAsync()와 Console.print()를 활용한다.

## 요구 사항

- 주어진 횟수 동안 n대의 자동차는 전진 또는 멈출 수 있다.
- 각 자동차에 이름을 부여할 수 있다. 전진하는 자동차를 출력할 때 자동차 이름을 같이 출력한다.
- 자동차 이름은 쉼표(,)를 기준으로 구분하며 이름은 **5자 이하**만 가능하다.
- 사용자는 몇 번의 이동을 할 것인지를 입력할 수 있어야 한다.
- 전진하는 조건은 0에서 9 사이에서 무작위 값을 구한 후 무작위 값이 4 이상일 경우이다.
- 자동차 경주 게임을 완료한 후 누가 우승했는지를 알려준다. **우승자는 한 명 이상일 수 있다.**
- 우승자가 여러 명일 경우 쉼표(,)를 이용하여 구분한다.
- 사용자가 잘못된 값을 입력할 경우 "[ERROR]"로 시작하는 메시지와 함께 Error를 발생시킨 후 애플리케이션은 종료되어야 한다.

### 게임 규칙

- 자동차 이름은 쉼표(,)로 구분하며 **5자 이하**만 가능하다.
- 전진 조건: 0~9 범위의 무작위 값이 **4 이상**일 경우 전진한다.
- 우승자는 **한 명 이상**이며, 여러 명일 경우 쉼표로 구분한다.

### 입력 검증

**자동차 이름**

- 최소 개수: 1대 이상
- 최대 개수: 100대 이하
- 최소 길이: 1자 이상
- 최대 길이: 5자 이하

**시도 횟수**

- 최소값: 1회 이상
- 최대값: 1000회 이하

**자동차 이름 검증**

- 입력값이 비어있지 않은가?
- 자동차 이름이 공백이 아닌가? (trim 후)
- 자동차 이름이 5자 이하인가?
- 중복된 이름이 없는가?

**시도 횟수 검증**

- 입력값이 비어있지 않은가?
- 숫자로 변환 가능한가?
- 정수인가?
- 양의 정수인가?

## 설계

초기 설계 단계에서는 함수형과 객체지향을 혼합한 멀티 패러다임 접근을 고려했습니다.
상태와 관련된 기능은 메서드로, 상태 관련 없는 단순 유틸 로직은 함수형으로 구성하는 방식을 고려했습니다.
하지만 상태 관리가 간단하고 요구사항도 단순해서 계층형 설계를 기반으로하는 **함수형 프로그래밍**으로 전환했습니다.

### 함수형으로 최종 결정한 이유

1. **명확한 로직 흐름** - 복잡한 클래스 구조 없이 함수 조합으로 직관적인 흐름을 표현합니다.
2. **구현 난이도에 적합** - 상태 관리의 부담이 적어 함수형이 더 효율적입니다.
3. **테스트 용이성** - 함수는 입출력이 명확하여 요구사항인 jest로 테스트하기 간단합니다.
4. **단일 책임 원칙** - 작은 함수들의 조합으로 관심사를 명확히 분리합니다.
5. **현대 프론트엔드 패러다임** - 리액트 등에서 사용되는 함수형 방식과 일치합니다.

### 파일 분리 기준

```
src/
├── constants/
│   ├── config.js              (상수값)
│   ├── errorMessages.js       (에러 메시지)
│   ├── outputMessages.js      (출력 메시지)
│   └── promptMessages.js      (입력 프롬프트)
├── domain/
│   ├── car.js                 (자동차 초기화)
│   ├── race.js                (경주 진행 로직)
│   └── result.js              (우승자 판정)
├── formatter/
│   └── raceFormatter.js       (경주 데이터 포맷팅)
├── validator/
│   ├── carsValidator.js       (자동차 입력 검증)
│   └── roundsValidator.js     (라운드 입력 검증)
├── ui/
│   ├── input.js               (사용자 입력)
│   └── output.js              (결과 출력)
└── App.js                     (메인 앱)
```

## 데이터 흐름

1. **validator** - 입력값 검증
    - carsValidator.js: carsInput → cars
    - roundsValidator.js: roundsInput → rounds

2. **domain** - 게임 로직 실행
    - car.js: cars → initialState
    - race.js: initialState, rounds → distanceRaceHistory
    - result.js: distanceRaceHistory → winnersArray

3. **formatter** - 데이터 변환
    - raceFormatter.js: distanceRaceHistory → dashRaceHistory

4. **ui** - 입출력 처리
    - input.js: 사용자 입력
    - output.js: dashRaceHistory, winnersString → 화면 출력

- **constants** - 모든 단계에서 사용되는 상수 및 메시지
